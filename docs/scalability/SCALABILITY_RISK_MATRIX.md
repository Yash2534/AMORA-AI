> Phase S3 update (2026-10-12): every remaining P0 shared-service risk now has an explicit staging architecture, validation procedure and acceptance gate. No staging resources or runtime artifacts are available, so priorities and horizontal-scaling status do not change. S4 readiness is **NO**.

> Phase S2 update (2026-10-12): plan-supported local changes reduce distance candidates, add chronology/queue indexes, remove a duplicate index, bound admin date/in-memory domains, aggregate financial totals in SQL, and close offer write races. Residual JSON/calculated discovery, reporting/count, deep-offset, and contention risks require production-like staging evidence; no capacity claim is made.

Shared realtime, distributed rate limits, shared private files, durable jobs, production observability, and measured capacity remain open. Exact traffic thresholds remain unknown.
